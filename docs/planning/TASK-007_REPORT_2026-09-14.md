## Findings and exact boundary attribution

The Motorola report (919 × 2047 px; left/right/top/bottom approximately 76/75/119/216 px)
establishes a visible 97 px vertical discrepancy, but does not identify its coordinate
inputs. **The exact cause on that phone is not yet established.** No Motorola is connected
to ADB. Claiming that its defect is fixed from the emulator would be unsupported.

The existing uniform-fit arithmetic already splits both remainders by two. The runtime
did assume that `Dimensions.window` was the rectangle occupied by the HUD host.
That assumption is now removed: `useHudFit` measures the host in window coordinates,
intersects it with the safe-area provider rectangle, and fits to that intersection.
This corrects the **native/window-to-render-host boundary** when those rectangles differ,
without changing reference dimensions or adding offsets. A browser test with a 430 × 932
window and a 430 × 850 host exercises that difference. It is a verified general correction,
not proof that this boundary caused the Motorola observation.

The continuation exposed a separate, reproduced React Native Web defect: measurement
was registered only after font loading, while the same root View had mounted without
`onLayout`. Its observer never attached, leaving the measured HUD invisible. Registering
measurement on the loading root fixes it. The regression now checks actual visibility
as well as dimensions.

## Fit policy and measured evidence

Given host bounds and effective safe insets:

```text
usableWidth  = host.width  - inset.left - inset.right
usableHeight = host.height - inset.top  - inset.bottom
scale = min(usableWidth / reference.width, usableHeight / reference.height)
fitted = reference * scale
remaining = usable - fitted
translation = remaining / 2
localOrigin = effectiveInset + translation
screenOrigin = hostOrigin + localOrigin
```

There is no scale ≤ 1 cap and no independent X/Y stretch. The visible border is a
sibling of the scaled artboard, inset **8 logical phone units** from the fitted frame.
Safe insets, aspect-ratio remainder and this border inset remain separate.

Development-only `HUD_FIT` output records screen, window, host, provider, original and
effective safe insets, usable size, layout ID, reference size, scale, fitted size,
remainders, translations, local/final bounds and the old window-based fit. It contains
no entry text. Rotation briefly delivers new screen axes before host/provider callbacks;
the trace retains these intermediate handoffs. Acceptance measurements below use the
settled host, not the transient record.

## Dock implementation

`HudDock` keeps body images mounted, waits for the complete body asset set to load, and
moves one Animated parent. Children do not mount/reveal individually on expansion.
YAML declares an assembled 240 ms cubic-out slide, with immediate motion when reduced
motion is enabled. Orientation changes reset the animation state before paint.

Figma's handle (299,340,77.5,27.5) is the collapsed rest position. Its expanded Y is
derived as dock.y − handle.height = 229.138. The body remains at the Figma expanded
position; the handle is attached directly above it throughout the 110.862-unit travel.
The reveal clip ends at the collapsed handle bottom, 367.5. This clips 4.415 units of
the parent's empty lower extent when expanded; the 350 × 96 bezel and visible children
are not clipped. No Figma values were edited to obtain this state behavior.

Browser animation samples verify intermediate motion, unchanged image/node identities
and a constant handle-bottom/dock-top relationship while opening and closing. Native
expanded bounds show handle bottom 890 equals dock/bezel top 890 physical pixels.
Native frame-by-frame animation perception on the Motorola remains part of user acceptance.

## Handedness implementation

Portrait YAML supports left and right. Landscape YAML supports canonical right only,
with `preference: preserve_portrait`. AppShell applies a left overlay only when supported.
Settings displays Left, dims it, exposes disabled accessibility state and prevents selection.
Landscape Right also does not write over the stored portrait choice.

Both browser and native emulator passed: portrait Left → landscape canonical Right
(Left disabled) → press Right → portrait Left restored. Native QA restored the original
Right preference afterward.
